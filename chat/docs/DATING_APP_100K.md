## 3. 추천: B

**같은 업체로 0명부터 10만 명까지 간다**

| 부분 | 커질 때 하는 일 |
|---|---|
| Supabase | 요금제·서버 크기만 올린다(코드 그대로) |
| Cloudflare | 자동으로 늘어난다 |

**Supabase에 Enterprise 계약이 필요 없다**
- 실시간 연결을 Cloudflare가 맡으므로 Supabase Realtime의 1만 연결 상한에 걸리지 않는다.
- DB는 33–47 vCPU가 필요하다. Supabase 최대 사양은 64 vCPU라 한 대 안에 든다.

**우리 서버가 없다**
- 새벽 장애 대응·보안 패치를 업체가 한다.
- 학생 사장님 + Claude 체제에서 지속 가능한 유일한 형태다.

**첫 달 비용**: Supabase Pro $25 + 작은 컴퓨트 + Workers Paid $5 + R2·TURN 사용량. 약 $50–100.

**C보다 월 약 $7,500 비싸다**
- 대부분 Supabase 월 활성 요금 $6,175다. 다른 로그인 제공자를 써도 같은 요금이다(공식: "$0.00325 per Third-Party MAU").
- 나중에 운영 인력이 생기면 DB만 우리 서버로 옮겨 이 차액을 아낄 수 있다. 같은 Postgres라 재작성이 아니다.
- 하지만 필수가 아니다.

## 4. 처음부터 넣어야 비용이 안 커지는 설계 (B 공통)

1. **폴링 금지**
   - 매칭·채팅·알림·통화 신호는 전부 Durable Objects WebSocket 푸시로 한다.
   - 쉬는 연결은 hibernation으로 둔다. 공식: 쉬는 객체는 시간 요금이 없고, 보내는 메시지는 무료다.
2. **매칭 엔진 = Durable Object**
   - (국가, 성별 조건)마다 하나씩 둔다. 객체당 초당 1,000요청이 한계라 버킷으로 나눈다.
   - 대기열은 메모리에, 확정된 매치만 DB에 저장한다.
3. **사진은 R2**
   - 썸네일 2종(WebP/AVIF, 40 KB 이하)을 쓰고, 다음 카드 2장만 미리 받는다.
   - Cloudflare 약관상 사진 대량 제공은 R2 같은 유료 개발자 플랫폼을 통해서만 할 수 있다.
4. **통화**
   - 랜덤·매치 상대와의 통화는 Cloudflare TURN 중계만 쓴다(IP 숨김).
   - 절약형 음질(44 kbps)은 출시 전 PESQ 측정으로 결정한다. 정하면 월 $7,500이 줄어든다.
5. **스와이프**: "좋아요"만 DB에 저장한다. "넘기기"는 사용자별 압축 목록(다시 안 보이게)으로 두어 DB 쓰기를 줄인다.
6. **인증번호**: 인도는 WhatsApp을 먼저 쓴다(`send-sms` 배포됨). 번호당 시간당 5건 제한, CAPTCHA.
7. **신원 확인은 단계형**(BUILD_VS_BUY §6-3). 기본은 전화번호, 신고·유료 기능일 때만 신분증.
8. **보관 기간·월 파티션**: 랜덤 채팅 30일 등 기존 정책을 유지해 DB 크기를 고정한다.

## 6. 확인하지 못한 것 (착수 전에 시제품으로 확인)

1. Durable Objects의 실제 비용
   - hibernation이 제대로 되면 $40–133이다.
   - 깨어 있는 객체가 많으면 수천 달러로 오를 수 있다(예: 늘 깨어 있는 객체 1,000개면 월 약 $4,100).
   - → 1만 WebSocket 부하 시험으로 잰다.
2. 사용 패턴 가정 T1–T9 전부. 특히 통화 비율(T2)과 사진 크기(T3)가 비용을 크게 움직인다.
3. Cloudflare TURN 월 1 TB 무료가 TURN 단독에도 적용되는지.
4. 법률: 랜덤 영상·음성 + 소개팅은 국가별 연령·데이팅 규제가 있다(BUILD_VS_BUY §9). Apple 1.2는 iOS 보류 결정과 일치한다.
