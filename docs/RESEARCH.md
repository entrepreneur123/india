### 결과가 올라오는 시점 (실측)

- **lotterysambad.com**: 추첨 후 약 7~10분 뒤 올라옵니다. PDF에 **텍스트 레이어가 있어 OCR 없이 정확히 파싱**됩니다.
  - 당일분은 `fetchtoday.php`, 과거분은 `lotteryoldresultsdown.php`로 받습니다. 약 1개월치가 남아 있습니다.
- **nagalandlotteries.com (공식)**: 하루치가 **20:28 IST 전후에 한꺼번에** 올라옵니다(Last-Modified 헤더로 확인). **스캔 이미지 PDF**입니다.
  - Tesseract로 읽어 보니 굵은 밑줄 숫자를 실제로 잘못 읽었습니다: `7587→2587`, `7536→2536`, `1247→124Z7`.
  - 그래서 공식 관보의 OCR 결과는 **검증용으로만** 씁니다. 여러 번의 OCR 결과가 전부 일치할 때만 채택합니다.

## 4. 인도 사용자 UX 원칙 (프로토타입에 반영한 것)

- 저사양폰과 느린 네트워크를 전제로 했습니다.
  - 릴리스 APK는 2.7MB입니다(R8 + 리소스 축소 + 3개 언어만 포함).
  - 결과 피드는 2개 추첨 기준 4KB입니다(7일치 예상 약 30KB, gzip 시 더 작음).
  - ETag 조건부 요청을 써서 바뀐 게 없으면 수백 바이트만 받습니다.
- 오프라인 우선입니다. 마지막 결과를 디스크에 캐시해 앱이 즉시 열리고, 데이터가 끊겨도 보입니다.
- 큰 숫자와 큰 터치 영역을 썼습니다. 1등 번호는 34sp 모노스페이스, 12시간제(1:00 PM)와 ₹1,00,00,000 인도식 자릿수 표기를 씁니다.
- WhatsApp으로 결과를 텍스트로 공유할 수 있습니다.
- 힌디어·벵골어 키보드의 현지 숫자(०-९, ০-৯) 입력도 인식합니다.

## 5. 리스크 (논의 필요)

1. **Sambad 데이터 의존**
   - 공개 PDF를 주기적으로 가져오는 구조입니다. 이용약관과 법적 검토가 필요하고, 사이트 구조가 바뀌면 파서가 깨집니다.
   - 파서는 깨질 때 **결과를 게시하지 않고 경고만 남기도록** 짜여 있습니다.
2. **GitHub Actions cron 지연**: 혼잡할 때 5~15분 이상 늦게 실행될 수 있습니다. 상용화하려면 Cloudflare Workers나 Cloud Run 같은 정확한 스케줄러로 옮겨야 합니다.
3. **Laxmi 4자리**: 공식 스캔 PDF만 있어서 OCR이 합의에 실패하면 "PDF 보기"만 제공합니다. 더 좋은 OCR(예: Google Cloud Vision)을 넣으면 개선됩니다.
4. **각 주의 복권 합법성**: 결과 정보 제공 자체의 위험은 낮다고 판단했지만(`미확인`), 판매 기능은 절대 넣지 않습니다.
